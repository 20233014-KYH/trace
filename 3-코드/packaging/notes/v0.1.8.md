출처 보기 · 링크 만들기가 훨씬 빨라졌어요.
- 출처 보기 분석이 22쪽 보고서는 0.1초, 100쪽 논문도 1초 안팎이에요 (전엔 AI 대화가 많으면 몇 분)
- AI 와 대화를 아주 많이 한 과제도 링크 · PDF 를 만들 수 있어요 (보고서와 대화가 크면 서버가 거절하던 것을 고침)
- 과제를 누를 때 서버에서 내역서 전체를 받지 않고 있는지만 물어요
- 결과(어디서 왔는지 · 일치 · 고침)는 전과 똑같아요

개발 메모
- core/match.py: 후보 글자 조각(bigram) 색인 · 기준(고침 30% · 그대로 90%)에 닿을 수 없는 후보는 건너뜀 (_문턱 · _그대로_될_수 증명은 주석) · 후보 SequenceMatcher 재사용 · 붙여넣기 한 색인(_라벨들) · latest_messages 정렬+bisect · _secs 기억
- app/source.py: 답마다 질문 찾기를 (세션, 도구)별 bisect 로
- 결과 같음 확인: tests/bench_big_report.py --dump 로 고치기 전 · 뒤 비교 (22쪽+대화 600 · 100쪽 · 100쪽+대화 1500 모두 바이트까지 같음) · 연결시제품 같은 ✗ 4개
- 시간 (이 맥): 22쪽 2.2초→0.09초 · 22쪽+대화 600 23초→0.5초 · 100쪽 40초→0.85초 · 100쪽+대화 1500 292초→3.5초
- server create_statement: 이벤트를 하나씩 묻던 것(d.get)을 한 번에 · Message/Link/Redaction 을 표마다 한 번에 INSERT → 100쪽 DB 1,713번 → 23번 (Render 싱가포르 ↔ Supabase 서울 한 번 ≈ 75ms)
- PC → 서버 64KB 넘는 JSON 은 UTF-8 + gzip (Content-Encoding: gzip) · 서버는 보낸 크기 5MB · 푼 크기 40MB 까지 (100쪽+대화 1500: 15MB → 2.9MB · 서버 메모리 최고 75MB)
- GET /works/<id>/statements/latest?brief=1 → id 만 (PC 가 과제를 누를 때 · 전엔 100쪽이면 10MB 를 4초 안에 받으려다 실패)
- 응답 압축은 Render 앞단(Cloudflare)이 이미 함 (br) — 서버에서 따로 안 함
- 시험: tests/bench_big_report.py (--pages · --chat · --screens · --dump) · tests/bench_server.py (DB 묻는 횟수 · --mem)
