# 1. 서비스 개요

**Trace(자국)** 는 대학생이 과제의 **작성 과정과 AI 사용 내역을 밝히는 일**을, 손으로 정리하지 않고 **자동 기록**으로 하도록 돕는 PC 프로그램·웹이다.

Trace는 사용자를 감시하거나 AI 사용 여부를 판정하지 않는다. 컴퓨터에서 실제로 일어난 일을 사실 그대로 기록하고, 그것을 학생이 확인한 뒤 학생이 제출한다.

# 3. 대상 사용자

**모든 학생이 아니다.**

- AI 허용 과제에서 **사용 사실·범위를 밝혀야 하는** 학생 (교육부 가이드라인)
- AI 답을 받아 **자기가 무엇을 고치고 판단했는지** 보여주고 싶은 학생
- 팀 과제에서 **자기 몫을 보여주고 싶은** 학생
- ~~AI 금지 과제에서 의심받는 학생~~ — **9/30 제외.** "안 썼다"는 Trace가 약속할 수 없다. 탐지기 오탐 사례는 "결과물만으로는 누가 얼마나 했는지 모른다"는 배경으로만 쓴다.

교수는 내역서 1장을 받고, **근거가 궁금할 때만** 링크를 연다. 교수는 Trace를 설치하지 않는다.

| 사례 | 해결 방식과 남은 한계 | 우리의 개선 방향 |
|---|---|---|
| **Grammarly Authorship** (미국) | 글 쓰는 창(구글 문서·Word) 안의 타이핑·붙여넣기·AI 사용을 자동 기록. 코드는 못 보고, 외부 AI 대화와 연결 못 해 보고 옮겨 친 글은 '직접 타이핑'으로 분류 | AI 서비스·VS Code·Word처럼 **여러 앱을 오가는 과정을 통째로** 기록해 '작성 과정 요약'이나 'AI 활용 내역서'로 만들어 줌 |

# 6. 바뀌지 않는 원칙 (코드 곳곳에서 지킨다)

1. **판정하지 않는다.** "AI 확률", 퍼센트 유사도, 등급, 점수를 화면·PDF·API 어디에도 내지 않는다. 사실(횟수·시각·출처·원문)만 낸다.
2. **기록 없는 부분은 "직접 씀"이 아니라 "출처 기록 없음"으로 표시한다.** Trace는 휴대폰·다른 PC에서 쓴 AI를 못 잡는다. 없는 걸 있다고, 있는 걸 없다고 단정하지 않는다.
3. **학생이 켜고, 학생이 확인하고, 학생이 제출한다.** 교수에게 자동으로 가는 경로는 없다.
4. **개인정보:** 과제 시작을 눌렀을 때만, 과제에 필요한 것만 기록한다. 학생이 확인한 뒤에만 밖으로 나간다. API 키·개인정보는 자동으로 가린다.
5. **해시 체인은 그대로.** PC와 서버 양쪽에서 만들고 대조한다(`core/chain.py`). 기록을 나중에 고치면 "조작됨"이 뜬다.
6. **"증명하는 것 / 증명하지 않는 것"을 나란히 쓴다.** "AI를 안 썼다"는 증명하지 않는다.

> 막히면: 판정·점수·퍼센트를 넣고 싶어지는 순간이 오면 이 절로 돌아온다.

# 7. 모드 없음 · 과제 유형 없음 (9/30)

`mode: learn | proof` 개념을 **없앤다.** 9/28 에 두었던 `ai_policy: "forbidden" | "allowed"` 도 **9/30 에 없앴다** — 대상이 AI 허용 과제뿐이라 고를 일이 없다.

과제에는 **`ai_scope`(선택 메모)** 만 둔다. 교수가 허용한 범위(예: "코드 설명·디버깅만 허용")를 적으면 내역서 맨 위에 그대로 찍힌다. Trace가 이걸로 판단하지는 않는다.

| 기록 | 출력 (AI 활용 내역서 1장) |
|---|---|
| 한 가지로 기록 (내용 포함) | 허용 범위(메모) · 쓴 AI · 질문 수 · 결과물에서 AI 답과 연결된 곳(그대로/고침) · 출처 기록 없음 구간 · 작업 시간 |

첫 실행 동의 화면의 **항목별 켜고 끄기**는 유지한다.

# 12. AI 답 연결 규칙 (⑩⑪ 공통)

```
붙여넣기 해시 == AI 답 해시     →  사실이므로 자동 연결
해시는 다르지만 내용이 비슷함   →  Trace가 제안, 학생이 맞다/아니다를 고름
  (고쳐서 붙임 · 보면서 다시 침 · 두 답을 합침)
```

- 학생이 "아니다"를 골라도 전체 기록에는 **"Trace가 연결을 제안했고 학생이 연결하지 않음"** 이 남는다. 지울 수 없고 체인에 포함된다.
- **퍼센트 유사도는 화면에 절대 내지 않는다.** 원문과 결과를 나란히만 보여준다.
- 비교 단위는 **문장**. 정확도가 부족하면 **문단** 단위로 축소한다.

# 13. 해시 체인

```
h_i = SHA256(h_{i-1} ‖ 시각 ‖ 종류 ‖ 요약)        h_0 = "0" * 64
```

`3-코드/core/chain.py` 하나를 기록기·서버·화면이 같이 쓴다. **여기 말고 다른 데서 해시를 계산하지 않는다.**

배치마다 체인 해시를 보내고 서버가 재계산해 대조한다. 어긋나면 `verified:false`, 봉인하면 409. 학생 PC에만 있으면 학생이, 서버에만 있으면 운영자가 고칠 수 있기 때문에 **양쪽에서 만들고 대조한다.**

**증명하는 것:** 기록된 내용의 순서와, 그 기록이 이후 바뀌지 않았다는 것.
**증명하지 않는 것:** "AI를 안 썼다". 다른 기기에서 쓴 AI. 대신 작업한 사람.

# 19. 차별점

기존 AI 탐지기는 **결과물만 보고 확률을 추정한다.** Grammarly Authorship은 과정을 기록하지만 **한 창 안에서만** 본다.

Trace는 **여러 앱을 오가는 과정을 통째로** 기록하고, **판정하지 않는다.** 같은 데이터라도 주인이 다르다 —
탐지기는 기관이 학생을 보게 하고, Trace는 **학생이 자기 과정을 보여주게 한다.**

# 20. 최종 서비스 정의

> **Trace(자국)는 대학생이 과제의 작성 과정과 AI 사용 내역을 밝히는 일을, 손 정리 없이 자동 기록으로 하도록 돕는 PC 프로그램·웹이다.**

- **기록** — 여러 앱을 오간 작성 과정 + AI 질문·답 (하나의 기록, 해시 체인으로 봉인)
- **AI 활용 내역서** — 요약 1장 PDF (AI 허용 과제)
- **공유 링크** — 교수가 내역서의 근거를 볼 때, 학생이 확인하고 가린 뒤에 여는 읽기 전용 과정
