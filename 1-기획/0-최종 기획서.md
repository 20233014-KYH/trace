# 1. 서비스 개요

## 1-1. 서비스명

**Trace(자국)**

Trace는 사용자가 컴퓨터로 학습하거나 작업하는 과정을 기록하고, 그 기록을 목적에 따라 두 가지 방식으로 활용하는 **작업 과정 기록 플랫폼**이다.

Trace는 사용자의 행동을 단순히 감시하거나 AI 사용 여부를 판정하는 것을 목적으로 하지 않는다.

대신 사용자가 컴퓨터에서 실제로 수행한 작업의 **과정과 맥락을 기록하고**, 그 기록을

- 자신의 학습을 돌아보기 위한 **Learn Mode**
- 작업 과정의 무결성을 증명하기 위한 **Proof Mode**

로 나누어 활용한다.

---

# 2. 문제 정의

AI의 발전으로 학생은 과제를 수행하거나 공부하는 과정에서 검색엔진, 생성형 AI, IDE, 문서 프로그램 등 다양한 도구를 동시에 활용하게 되었다.

이러한 환경에서 최종 결과물만으로는 사용자가 **어떤 과정을 거쳐 결과에 도달했는지** 알기 어려워졌다.

예를 들어 동일한 결과물을 제출하더라도,

> 직접 오류를 찾고 공부하면서 완성한 경우

와

> AI가 제공한 답변을 그대로 가져와 완성한 경우

는 학습 과정에서 큰 차이가 있다.

그러나 최종 결과물만 제출하는 현재의 방식에서는 이러한 차이를 확인하기 어렵다.

또한 AI 사용이 금지된 과제, 컴퓨터 기반 시험, 코딩 테스트, 공모전 등의 상황에서는 결과물뿐 아니라 **작업 과정이 실제로 어떻게 이루어졌는지**를 보여줄 필요가 있다.

따라서 Trace는 결과물이 아닌 **과정 자체를 기록하는 것**에 주목한다.

---

# 3. Trace가 해결하려는 두 가지 문제

Trace는 하나의 기록 시스템을 서로 다른 두 가지 목적에 활용한다.

## 문제 ① 학습 과정은 결과물만으로 알기 어렵다.

학생이 무엇을 어려워했는지, 어떤 부분에서 검색이나 AI를 활용했는지, AI의 도움 이후 실제로 무엇을 이해하고 수정했는지 등을 최종 결과물만으로는 확인하기 어렵다.

### 해결

**Learn Mode**

사용자의 작업 이벤트뿐만 아니라 필요한 작업 내용과 맥락까지 수집하고 AI가 이를 분석하여,

- 어떤 부분에서 어려움을 겪었는지
- 어떤 질문을 했는지
- 어떤 자료를 참고했는지
- AI의 도움을 어떻게 활용했는지
- 이후 무엇을 직접 수정했는지
- 어떤 개념을 학습했는지

를 분석한다.

---

## 문제 ② 작업 결과만으로는 작업 과정의 진위를 설명하기 어렵다.

AI 사용이 제한되는 과제나 시험에서는 결과물만으로 사용자가 실제로 어떤 과정을 거쳤는지 설명하기 어렵다.

### 해결

**Proof Mode**

작업의 세부 내용 자체를 수집하는 것이 아니라,

- 어떤 프로그램을 사용했는지
- 언제 작업했는지
- 어떤 이벤트가 발생했는지
- 어떤 순서로 작업이 이루어졌는지

를 기록하고 이를 Hash Chain으로 연결한다.

작업 종료 후 기록을 봉인하여 기록의 변경 여부와 순서를 검증할 수 있도록 한다.

---

# 4. 핵심 서비스 구조

Trace는 하나의 기록 시스템을 두 가지 목적에 맞게 사용한다.

| 구분 | Learn Mode | Proof Mode |
| --- | --- | --- |
| 목적 | 학습 과정의 이해와 정리 | 작업 과정의 무결성 증명 |
| 시작 시점 | 공부·과제·프로젝트 등을 학습 목적으로 시작할 때 | AI 사용 제한 작업의 증명이 필요할 때 |
| 이벤트 기록 | O | O |
| 이벤트 내용/맥락 | **O** | **X** |
| AI 사용 | 허용 | 사용하지 않는 전제 |
| AI 질문/답변 분석 | O | X |
| 작업 내용 분석 | O | X |
| AI Side Chat | O | X |
| Hash Chain | 선택적 활용 | **핵심 기능** |
| 종료 후 결과 | **Learning Session Report** | **Proof Certificate** |

즉,

> **Learn Mode는 기록을 이해하기 위해 사용하고, Proof Mode는 기록을 증명하기 위해 사용한다.**

---

# 5. Learn Mode

## 5-1. 목적

Learn Mode는 사용자가 평소 공부하거나 작업하는 과정을 기록하고, 그 과정에서 발생한 행동과 내용을 분석하여 **자신이 무엇을 학습했고 어디에서 어려움을 겪었는지 확인할 수 있도록 하는 모드**이다.

Learn Mode에서는 AI 사용을 금지하거나 판단하지 않는다.

AI에게 질문하는 것도 하나의 학습 과정으로 기록될 수 있으며, 중요한 것은 **AI를 사용했는지 여부가 아니라 AI를 사용한 이후 학습 과정이 어떻게 이어졌는지**이다.

---

# 6. Learn Mode의 핵심: 이벤트가 아니라 이벤트의 맥락

단순한 이벤트 기록만으로는 학습 과정을 충분히 이해할 수 없다.

예를 들어 다음과 같은 기록이 있다고 가정한다.

```
14:05  VS Code 오류 발생
14:06  AI 사이트 접속
14:07  200자 복사
14:07  VS Code 붙여넣기
14:08  코드 수정
14:09  다시 실행
14:09  오류 해결
```

이 기록만으로는 학생이 왜 AI를 사용했는지 알 수 없다.

따라서 Learn Mode에서는 이벤트뿐 아니라 **필요한 범위의 내용과 맥락(Context)**도 함께 수집한다.

예를 들어,

```
14:05
NullPointerException 발생

14:06
AI에게 질문
"NullPointerException이 발생하는 이유가 뭐야?"

14:07
AI 답변 중 관련 내용 200자 복사

14:07
VS Code 특정 위치에 붙여넣기

14:08
학생이 코드 직접 수정

14:09
재실행

14:09
오류 해결
```

이렇게 되면 AI는 단순히

> "AI를 사용했다."

가 아니라,

> "NullPointerException의 원인을 이해하지 못해 AI에게 질문했고, 답변을 참고한 뒤 코드를 수정하여 오류를 해결했다."

라는 **학습 과정의 맥락**을 분석할 수 있다.

---

# 7. Learn Mode의 기록 구조

Learn Mode는 크게 두 종류의 데이터를 사용한다.

## 7-1. Event Log

사용자가 컴퓨터에서 무엇을 했는지를 기록한다.

예:

- 프로그램 실행
- 프로그램 전환
- 웹사이트 방문
- 파일 생성/수정/저장
- 복사/붙여넣기
- 코드 실행
- 오류 발생
- Git Commit

Event Log는 Proof Mode와 기본적으로 공유할 수 있다.

---

## 7-2. Context Log

해당 이벤트가 **어떤 내용과 맥락에서 발생했는지**를 기록한다.

예:

### Browser

- 방문 페이지
- 학습 관련 페이지
- AI에게 입력한 질문
- 사용자가 선택한 관련 텍스트
- AI 답변의 관련 내용

### VS Code

- 수정된 코드
- 실행 결과
- 오류 내용
- 코드 변경 내용
- 실행 → 오류 → 수정 → 재실행의 흐름

### 문서 작업

향후 지원 범위에 따라

- 작성 내용의 변화
- 수정된 부분
- 복사/붙여넣기
- 문서 작성 흐름

등을 기록할 수 있다.

단, 모든 화면이나 모든 개인정보를 무차별적으로 수집하는 방식이 아니라 **학습 분석에 필요한 범위의 정보만 수집하는 것을 원칙으로 한다.**

---

# 8. Learn Mode AI 분석

수집된 Event Log와 Context Log를 AI가 함께 분석한다.

AI는 다음과 같은 내용을 찾아낸다.

### ① 학습 집중 영역

사용자가 어떤 주제나 작업에 가장 많은 시간을 사용했는지 분석한다.

### ② 어려움을 겪은 지점

오류, 반복 검색, AI 질문, 반복 수정 등의 패턴을 통해 어려움을 겪은 부분을 찾아낸다.

### ③ 학습 과정

질문 → 참고 → 적용 → 수정 → 재시도와 같은 흐름을 분석한다.

### ④ AI 활용 과정

AI를 사용했다는 사실만 기록하는 것이 아니라,

> 질문 → 답변 참고 → 적용 → 수정 → 결과

의 과정을 분석한다.

### ⑤ 학습 포인트

세션에서 새롭게 등장하거나 반복적으로 다뤄진 개념을 정리한다.

### ⑥ 미완성 학습 지점

AI나 검색을 통해 답을 얻었지만 이후 직접적인 적용이나 이해 과정이 부족한 부분을 찾아낼 수 있다.

---

# 9. Learn Mode Side Chat

Learn Mode에서는 작업 중 이해되지 않는 부분을 사용자가 직접 선택하여 AI에게 질문할 수 있다.

예를 들어 코드나 문서에서 이해되지 않는 부분을 선택하면 화면 한쪽에 Side Chat이 나타난다.

```
┌─────────────────────┬──────────────┐
│                     │              │
│      작업 화면       │   Learn AI   │
│                     │              │
│   이해되지 않는      │ "이 부분은   │
│   코드 선택          │  왜 이렇게    │
│                     │  작성돼?"     │
│                     │              │
└─────────────────────┴──────────────┘
```

AI에게 묻는 길은 두 가지다. 하나는 위처럼 **이해되지 않는 부분을 선택**했을 때 뜨는 작은 툴바에서 여는 것이고, 다른 하나는 기록 중 화면 구석의 **알약(기록 표시) 위에 항상 떠 있는 작은 질문칸**이다. 질문칸을 누르면 그 자리 위로 채팅 패널이 펼쳐지고, 닫으면 다시 질문칸만 남는다. 브라우저의 AI 사이트로 옮겨 가지 않아도 작업 화면 안에서 바로 물을 수 있게 하기 위해서다. 두 길 모두 같은 Learn AI 로 이어지며, Proof Mode에는 질문칸이 없다.

이 대화 역시 Learn Mode의 학습 과정과 연결된다.

따라서 단순한 AI 챗봇이 아니라 **사용자의 실제 작업 맥락 안에서 작동하는 학습 보조 기능**이 된다.

---

# 10. Learn Mode 종료 후 Learning Session Report

학습 세션이 끝난 뒤 학생이 리포트를 열면, 그때 Trace AI가 해당 세션의 Event Log와 Context Log를 종합하여 **Learning Session Report**를 생성한다. (세션 종료 시 자동 생성하지 않는다 — 학생이 보지 않는 세션에는 AI 비용을 쓰지 않기 위해서다.)

예:

### 이번 세션의 주요 학습 내용

- Java 예외 처리
- NullPointerException
- 객체 참조 및 초기화

### 가장 많은 어려움을 겪은 부분

- 객체 초기화 과정
- NullPointerException의 발생 원인

### 학습 과정

오류 발생 → 오류 원인 검색 → AI에게 질문 → 답변 참고 → 코드 적용 → 직접 수정 → 재실행 → 오류 해결

### 학습 포인트

- NullPointerException이 발생하는 상황
- 객체 참조와 초기화의 관계
- 오류 메시지를 이용한 디버깅 방법

### 추가 학습이 필요한 부분

- 객체 생성과 참조 변수의 차이
- 예외 발생 원인 직접 추적하기

이렇게 Learn Mode의 최종 결과물은 단순한 로그가 아니라 **한 번의 학습 세션을 정리한 보고서**가 된다.

---

# 11. Proof Mode

## 11-1. 목적

Proof Mode는 사용자가 **AI 사용이 제한되거나 작업 과정의 증명이 필요한 상황**에서 사용한다.

예:

- AI 사용 금지 과제
- 컴퓨터 기반 시험
- 코딩 테스트
- 공모전
- 실기/디지털 작업
- 기타 작업 과정의 증명이 필요한 상황

Proof Mode에서는 학습을 돕거나 AI에게 질문하는 기능을 제공하지 않는다.

사용자는 Proof Mode를 시작하고 자신의 작업을 수행한다.

---

# 12. Proof Mode의 핵심 원칙

Proof Mode는 **작업 내용 자체를 저장하는 것이 아니라 작업이 이루어진 사실과 순서를 기록하는 것**에 집중한다.

예:

```
14:03  VS Code 실행
14:07  Chrome 실행
14:09  파일 생성
14:12  입력 240자 · 삭제 18자
14:15  코드 수정
14:20  코드 실행
14:20  오류 발생
14:22  복사 200자 (chrome.exe · Claude)
14:23  붙여넣기 200자 → VS Code
14:24  코드 수정
14:25  정상 실행
14:30  Word 실행
14:31  붙여넣기 100자 → Word
14:31  Word 문서 · 문단 2 · +100자
14:35  Word 저장 · 1,530자
```

이벤트의 세부 내용이나 AI에게 입력한 질문 및 답변은 기록하지 않는다.

키 입력·삭제·되돌리기는 **횟수만** 기록한다. 어떤 키를 눌렀는지, 무슨 글자를 쳤는지는 기록하지 않는다. 복사·붙여넣기는 **글자 수와 해시**만 기록하며, 붙여넣은 내용의 해시가 앞선 복사의 해시와 같으면 "어느 창에서 복사한 것"으로 표시한다. Word·PowerPoint 문서는 **어느 문단·슬라이드가 몇 자 늘고 줄었는지**와 저장 시점의 분량만 기록하고, 글의 내용은 저장하지 않는다. 이는 판정이 아니라 사실의 표기이며, AI 사용 여부를 추정하는 점수는 만들지 않는다.

따라서 Proof Mode는 개인정보와 작업 내용의 불필요한 수집을 최소화하면서 **작업 과정 자체의 기록**에 집중할 수 있다.

---

# 13. Proof Mode Hash Chain

Proof Mode에서는 기록된 이벤트를 순서대로 Hash Chain으로 연결한다.

```
Event 1 → Hash 1 → Event 2 + Hash 1 → Hash 2 → Event 3 + Hash 2 → Hash 3 → … → Root Hash
```

개념적으로:

`hᵢ = SHA256(hᵢ₋₁ || timestamp || event summary)`

이 구조를 통해 기록된 이벤트의 순서가 연결되며, 이후 특정 이벤트가 임의로 변경되었을 경우 Hash Chain의 무결성이 깨지게 된다.

Hash Chain은 **학생 PC에서 이벤트가 발생할 때마다 생성**되며, 이벤트는 5초 단위로 서버에 전송된다. 서버는 수신한 이벤트로 **같은 방식으로 체인을 재계산**하여 학생 PC가 보낸 해시와 일치하는지, 그리고 각 이벤트가 발생 시각으로부터 얼마나 늦게 도착했는지를 기록한다. 불일치나 지연 수신은 숨기지 않고 Certificate에 그대로 표시한다. 세션 종료 시 서버는 전체 체인을 다시 계산해 Root Hash를 확정하고 외부(OpenTimestamps)에 Anchor한다.

이렇게 **양쪽에서 만들고 대조**하는 이유는 두 가지다. 학생 PC에만 있으면 학생이, 서버에만 있으면 운영자가 기록을 고칠 수 있다. 양쪽이 서로를 확인하면 어느 한쪽도 혼자 고칠 수 없고, 학생 PC에 남은 사본과 Anchor만으로 **서버 없이도 제3자가 검증**할 수 있다.

---

# 14. Proof Certificate

Proof Mode가 종료되면 **Proof Certificate**를 생성한다.

Certificate에는 예를 들어 다음 정보가 포함된다.

- Work ID
- Session ID
- 작업 시작/종료 시간
- 기록된 이벤트 수
- 사용 프로그램
- 작업 세션의 Hash Root
- Seal 정보
- 검증 방법

이를 통해 제3자는 해당 기록이 생성된 이후 변경되었는지 검증할 수 있다.

단, Proof Mode가 증명하는 것은 **기록된 작업 로그의 무결성과 순서**이다.

따라서 다음을 절대적으로 증명하는 시스템으로 정의하지 않는다.

> "AI를 사용하지 않았다."

대신,

> **"이 시간 동안 이 작업 과정이 기록되었으며, 해당 기록이 이후 임의로 변경되지 않았음을 검증할 수 있다."**

라는 범위에서 Proof를 제공한다.

---

# 15. 두 모드의 관계

Learn Mode와 Proof Mode는 동일한 기반 기술을 사용하지만 사용자의 목적은 다르다.

```
                    Trace
                      │
             ┌────────┴────────┐
             │                 │
        Learn Mode         Proof Mode
             │                 │
       학습 과정 이해       작업 과정 증명
             │                 │
     Event + Context         Event
             │                 │
       AI 분석 / Chat       Hash Chain
             │                 │
   Learning Session Report  Proof Certificate
```

따라서 두 모드를 하나의 사용자 흐름으로 합치지 않는다.

사용자는 작업을 시작할 때부터 자신의 목적에 따라 모드를 선택한다.

# 16. 공통 데이터 수집 구조

두 모드가 공유하는 핵심 인프라는 **Trace Collector**이다.

## 16-1. Python Collector

운영체제 수준에서 기본적인 이벤트를 수집한다.

예: 세션 시작/종료 · 활성 프로그램 · 활성 창 · 유휴 시간 · 파일 생성/수정/저장 · Clipboard 이벤트

## 16-2. Browser Extension

브라우저에서 필요한 정보를 수집한다.

### Proof Mode
- 도메인 · 페이지 전환 · 체류 시간 · 브라우저 이벤트

### Learn Mode
필요한 경우 추가적으로 AI 질문 · 선택한 텍스트 · 관련 답변 · 학습 페이지의 맥락 등을 수집한다.

## 16-3. VS Code Extension

### Proof Mode
- 코드 편집 이벤트 · 실행 · Debug · 오류 · Git Commit

### Learn Mode
추가적으로 코드 변경 내용 · 오류 내용 · 수정 과정 · 실행 결과 · AI 도움 이후의 코드 변화 등을 분석할 수 있도록 한다.

## 16-4. 이번 학기 수집 범위

Learn Mode의 Context는 앱마다 수집 모듈이 다르므로 우선순위를 정해 순서대로 만든다. **시간이 부족하면 브라우저까지만** 하고 나머지는 다음 학기로 넘긴다.

| 순서 | 대상 | 방법 | 수집하는 Context |
| --- | --- | --- | --- |
| 1 · **Must** | 브라우저 (Chrome) | 확장 (MV3) | AI에게 입력한 질문 · 답변 중 복사한 부분(≤500자) · 선택한 텍스트(≤200자) · 방문한 학습 페이지 |
| 2 · Should | VS Code | 확장 (Extension API) | 오류 내용 · 코드 변경 · 실행 결과 · 선택한 코드 |
| 3 · Should | Word · PowerPoint | Office 자동화 (COM) | 문서의 변경된 부분 · 붙여넣은 위치 · 저장 시점의 분량 변화 |

Proof Mode는 이 표와 무관하게 Context를 수집하지 않는다. Python Collector(OS 이벤트)는 두 모드에서 동일하며 내용을 읽지 않는다.

---

# 17. 데이터 수집 원칙

Trace는 모든 데이터를 무조건 수집하는 방식으로 설계하지 않는다.

## Proof Mode

**최소한의 이벤트 정보만 수집**

> "무엇을 했는가?"

를 기록한다.

## Learn Mode

학습 분석에 필요한 범위에서

> "무엇을 했고, 무엇을 보고/입력/수정했는가?"

를 기록한다.

따라서 Learn Mode에서도 화면 전체를 지속적으로 녹화하거나 사용자의 모든 개인정보를 수집하지 않는다.

앱별 Collector/Extension을 통해 **목적에 필요한 Context만 선택적으로 수집**한다.

Learn Mode에서 수집하는 Context는 **항목별로 켜고 끌 수 있다** — AI 질문 · 답변 발췌 · 선택 텍스트 · 학습 페이지 · Side Chat 대화 각각. 어떤 항목을 켰는지는 첫 실행 화면과 설정 화면에서 항상 볼 수 있으며, 끈 항목은 수집기와 확장이 아예 전송하지 않는다.

두 모드의 기록은 모두 학생 PC에 먼저 저장되고, 학생 계정에 동기화된다. Learn Mode의 기록은 **학생 본인만 본다** — 교수나 제3자에게 자동으로 공유되는 경로는 없으며, 밖으로 나가는 것은 학생이 직접 내보낸 Learning Session Report(PDF)뿐이다.

# 19. Backend가 필요한 이유

서버는 다음과 같은 데이터를 관리한다: **User**(계정) · **Work**(하나의 학습/작업 단위) · **Session**(Work 안에서 실제 작업이 이루어진 개별 세션) · **Device** · **Event** · **Context**(Learn Mode 작업 내용 및 맥락) · **Proof Chain** · **Report** · **Certificate**

---

# 20. DB가 필요한 이유

기존 단순 프로토타입에서는 JSON 파일에 데이터를 저장할 수 있지만 실제 서비스에서는 한계가 있다. User → Work → Session → Events/Context 로 데이터가 축적되고, 여러 기기에서 동일한 Work를 이어서 수행하거나 이전 학습 기록을 조회하려면 서버 기반 DB가 필요하다.

---

# 21. React가 필요한 이유

Trace는 단순한 결과 페이지가 아니라 사용자가 자신의 작업 과정을 탐색하는 서비스이다. Work Dashboard · 실시간 Session 화면 · Timeline · 이벤트 상세 화면 · Learn Mode Side Chat · Learning Session Report · Proof Certificate · Work/Session 관리 등의 인터랙티브 UI를 구현한다.

---

# 22. AI가 필요한 이유

Learn Mode에서 AI는 기록된 Event와 Context를 분석하여 **사용자의 학습 과정을 구조화하는 역할**을 한다.

- 입력: 시간 · 프로그램 · 작업 이벤트 · 검색/AI 질문 · 코드 변화 · 오류 · 수정 과정 · 사용자가 참고한 내용
- 출력: 학습 주제 · 어려움을 겪은 지점 · 학습 과정 · 주요 학습 포인트 · 반복된 문제 · 추가 학습이 필요한 부분 · Learning Session Report

# 24. MVP 우선순위

1. **공통 기반** — Python Collector · Backend · DB · React · User/Work/Session 구조
2. **Proof Mode** — Event Logging · Hash Chain · Proof Certificate
3. **Learn Mode** — Browser Context · VS Code Context · AI 분석 · Learning Report

# 25. Trace의 차별점

기존 AI 서비스는 사용자의 질문에 답하거나 결과물을 만들어주는 데 집중한다. 기존 기록 서비스는 사용자의 행동을 기록하는 데 집중한다.

Trace는 그 사이에서 **작업 과정 자체를 하나의 데이터로 만든다.**

- Learn Mode: 행동 기록 → 내용/맥락 수집 → AI 분석 → 학습 과정 정리
- Proof Mode: 행동 기록 → Hash Chain → 무결성 검증 → Certificate

동일한 Collector 인프라를 기반으로 하면서도 **기록을 사용하는 목적 자체를 분리**한다.

# 26. 기대 효과

## 학생
자신이 어떤 부분에서 어려움을 겪었고 무엇을 학습했는지 확인할 수 있다. 단순히 완성된 결과물을 저장하는 것이 아니라 **자신의 학습 과정 자체를 자산으로 만들 수 있다.**

## 교수 · 검증자
Proof Mode에서는 학생이 제출한 **Proof Certificate**로 작업 과정의 순서와 무결성을 확인할 수 있다. 설치 없이 검증 페이지에서 확인 파일(.json + .ots)만 올리면 된다.

Learn Mode의 기록은 학생 본인을 위한 것이며 교수에게 자동으로 공유되지 않는다. 학생이 원할 때 **Learning Session Report를 PDF로 내보내** 피드백을 요청할 수 있다. Trace는 이 리포트를 평가 자료로 쓰는 것을 전제하지 않는다.

## AI 제한 환경
AI 사용이 제한된 과제나 시험에서는 작업 과정에 대한 별도의 기록을 제공할 수 있다.

---

# 27. 서비스의 핵심 가치

Trace가 기록하는 것은 단순한 컴퓨터 사용 기록이 아니다. **사람이 결과에 도달하기까지 남긴 자국이다.**

Learn Mode에서는 그 자국을 통해 **"나는 무엇을 배우고 있었는가?"** 를 돌아보고, Proof Mode에서는 **"이 작업은 어떤 과정으로 이루어졌는가?"** 를 보여준다.

결국 Trace는 결과물만 남는 디지털 작업 환경에서 **과정을 하나의 데이터이자 자산으로 만드는 서비스**를 목표로 한다.

---

# 28. 최종 서비스 정의

> **Trace(자국)는 사용자의 디지털 작업 과정을 기록하고, 그 기록을 학습과 증명이라는 서로 다른 목적에 맞게 활용하는 과정 기록 플랫폼이다.**

- **Learn Mode** — 이벤트 + 내용/맥락 → AI 분석 → Learning Session Report
- **Proof Mode** — 이벤트 + 시간/순서 → Hash Chain → Proof Certificate
- **공통 기반** — Collector → Backend → DB → React

## 한 문장으로

> **결과만 남는 작업에서, 과정을 남긴다.**
