| 넣을 것 | 어디서 |

## 9장. 시스템 설계 — 원문은 학생 PC에 남는다 (30초)

**한 문장:** 원문은 학생 PC에 남고, 서버에는 해시와 학생이 고른 것만 간다.

**요구 문구 "Frontend – Backend – Database"에 맞춰 이름을 붙여 준다** (그림 옆 작은 표):

| | 무엇 | 기술 |
|---|---|---|
| Frontend | 학생: PC 앱 화면 · 교수: 내역서 웹 화면 | HTML/JS (pywebview) · 브라우저 |
| Backend | PC 기록기 · 출처 잇기 · 다듬기 (로컬) / 서버 (로그인 · 해시 확인 · 내역서 PDF · 링크) | Python · Chrome 확장 · Flask · Render(싱가포르) · reportlab · 구글/카카오 로그인 |
| Database | 서버: 해시 · 내역서 · 링크 / PC: 원문 파일 | Supabase (PostgreSQL) · PC 로컬 파일 |

- 그림: `2-architecture.png` (11/1 고침 — 다듬기를 지금 돌아가는 것으로)
- **데이터 흐름 3단계로 말하기:** ① 기록 중 → 서버엔 **해시만** ② 제출 때 → 학생이 고른 원문만 (가린 뒤) → 서버가 해시로 다시 계산해 **조작 확인** ③ 교수 → 비밀 링크로 읽기만
- 대본: "AI 답과 학생 글의 원문은 기록하는 순간 학생 PC에만 저장됩니다. 서버에는 해시만 가고, 제출할 때 학생이 고른 원문이 오면 서버가 해시로 다시 계산해 바뀐 게 없는지 확인합니다. 교수는 계정 없이 링크로 읽기만 합니다."

**받을 질문**
- "해시가 뭐야 / 왜 써?" → "글의 지문입니다. 원문 없이도 나중에 온 글이 기록 때와 같은지 확인할 수 있습니다."
- "서버가 해외인데?" → "Render 싱가포르입니다. 실제 수업 전에 국외 이전 동의 문구를 넣습니다 (11장 예상 문제)."

## 10장. DB 설계 — 지금 테이블에 2가지만 더한다 (30초)

**한 문장:** 지금 테이블에 다듬기와 보관 기간 2가지만 더하면 v2.2가 된다.

- 그림: `3-erd.png`
- **말할 줄기 하나:** 학생(`users`) → 과제(`works`) → 기록 한 번(`sessions`) → 기록 이벤트(`events`, **원문 대신 해시**) / 과제 → 내역서(`statements`) → 보여 준 원문 · 출처 결정 · 가린 것 · 교수 링크
- 더하는 것: **`checks`** (다듬을 곳 종류 · 학생 처리 → "다듬음 N", 원문 없음) · **`statements.retain_until`** (보관 기간)
- 모아 보기(`assignments`)는 하지 않음 → 슬라이드에서 뺌 (11/2)
- 표 하나하나 설명하지 않는다. 쉬운 풀이가 필요하면 → 대화 기록의 "ERD 표 풀이" (users · tokens · works · sessions · events · statements · messages · links · redactions · shares · checks)
- 슬라이드에서 빼도 되는 것: `batches · contexts` (`contexts`는 옛 기능 흔적, 지금 기록기가 안 씀) · 로그인 보조 표 3개 → 넣으면 선만 많아짐

**받을 질문**
- "로그인 토큰을 왜 JWT 말고 DB에?" → "학생 기록을 다뤄서 '이 기기 연결 끊기'가 돼야 합니다. JWT는 서버가 못 끊습니다." (`server/db.py` 주석)
- "교수가 원문을 어떻게 봐?" → "학생이 제출 때 고른 질문 · 답만 `messages`에 오고, 서버가 해시로 기록과 맞는지 확인합니다."
- "가린 건?" → "어느 기록을 가렸는지만 남고 내용은 서버에 안 옵니다 (`redactions`)."
