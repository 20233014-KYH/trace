## 3. B가 해 놓은 것 (A가 받아서 쓸 것)

### 3-1. 수집기 — 계약의 "수집기 쪽" 5개 동작 전부

```
시작   POST /api/works/{work}/sessions      {id(UUID), mode, device, started_at}
전송   POST /api/sessions/{id}/events       5초 또는 50건마다 · {events[], chain_head, chain_len}
종료   POST /api/sessions/{id}/end          {ended_at, chain_len, root}
오프라인  queue.jsonl 에 순서대로 보관 → 살아나면 재전송 (옛 세션은 옛 id로)
로컬   events-날짜.jsonl 에 항상 먼저 기록 (이벤트마다 체인 해시 h 포함)
```

### 3-2. 참고 서버 `collector/dev_receiver.py` — A의 Backend 기준

계약 3절을 그대로 구현한 Flask 서버 (메모리 저장, 인증 없음). **엔드포인트·요청·응답 형식은 이대로 두고 저장만 DB로** 바꾸면 Backend가 된다.

| 엔드포인트 | 하는 일 |
|---|---|
| `POST /api/works/<w>/sessions` | 세션 등록 (같은 id 다시 오면 200) |
| `POST /api/sessions/<id>/events` | batch 수신 → `3-코드/core/chain.py`로 체인 재계산 → `chain_head` 대조 → `received_at` 기록 → 5분 넘게 늦으면 지연 카운트 → heartbeat는 저장 안 하고 마지막 시각만 |
| `POST /api/sessions/<id>/end` | 전체 체인 재계산 → root 대조 → 봉인 · 앵커 pending (OTS 실제 제출은 A) |
| `GET /api/sessions/<id>` | `3-코드/core/derive.py`로 화면용 session.json |
| `GET /api/sessions/<id>/events` | 원본 이벤트 (페이징) |

**핵심: `3-코드/core/chain.py` 하나를 수집기·서버·derive가 같이 쓴다.** 해시 계산을 다른 데서 다시 짜지 말 것 — 한 글자만 달라도 "불일치"가 된다. Backend가 파이썬이면 그대로 import, 아니면 이 파일을 그 언어로 옮기고 같은 입력에 같은 해시가 나오는지 테스트 픽스처로 확인.

### 3-3. 실테스트 결과 (9/20 · B 본인 7분)

```
수집 49건 → batch 전송 전부 "체인 일치" → 봉인 검증됨 (root da74f0c3…)
Claude 앱 복사 → 카카오톡 붙여넣기 : 같은 해시 · AI 앱 출처 ✓
탐색기 복사 → Claude 붙여넣기     : 같은 해시 · AI 아님 ✓ (잘못 빨강 안 됨)
크롬 ChatGPT 탭                  : 제목 키워드로 [ai] ✓ (확장 전 임시)
오프라인 큐 → 재전송              : 옛 세션 옛 id로, 새 세션 따로 봉인 ✓
```
테스트로 잡은 버그 3개(구간 초 단위 · 화이트리스트 밖 앱 뭉침 · 큐 재전송 세션 id)는 고쳐져 있음.
