## 1. 이 프로젝트가 무엇인가

**창작 과정 증명 서비스.** 창의프로젝트1 (2026-2학기, 박재완 교수), 2인 1팀.

글·그림을 만드는 사람이 "이 순서로, 이 시간 동안 만들었고 그 기록은 사후에
고쳐지지 않았다"를 제3자에게 보일 수 있게 한다.

### 증명하는 것 / 증명하지 않는 것

| 증명한다 | 증명하지 않는다 |
|---|---|
| 기록이 사후에 변조되지 않았음 | **"AI가 아니다"** — 판정하지 않는다 |
| 언제·몇 세션·어떤 곡선으로 진행됐는지 | 대리 작업 (범위 밖) |
| 붙여넣기·되돌리기·유휴 이벤트 | 결과물의 품질·독창성 |

**포지셔닝** — "위조 불가"가 아니라 **"위조 비용 = 실제 작업 비용"**.
1시간짜리 기록을 위조하려면 1시간을 써야 한다.

### 핵심 원칙 (어기면 기획이 무너짐)

1. **판정하지 않는다.** AI 점수·등급·경고 문구를 넣지 않는다. 지표는 자료이지 결론이 아니다.
2. **내용을 서버에 저장하지 않는다.** 해시와 이벤트 카운트만 보낸다.
3. **공백을 숨기지 않는다.** 수집기가 꺼져 있던 구간은 그대로 표시한다.
4. **보는 사람은 작가가 아니다.** 검증 화면의 독자는 의뢰인·교수·심사위원이다.
   8.2 기준: **검증자가 30초 안에 결론이 나야 한다.**

## 2. 이번 주 과제 요건 (이것만 충족하면 됨)

> - 하나의 페이지를 구현해보기
> - **데이터베이스(json)의 데이터가 웹페이지(front)에 나타나는 것이 중요**
> - **데이터 흐름에 집중할 것**

강의자료 기준 **STEP 1** = HTML/CSS/JS + Flask + JSON File.
React, 서버형 DB, 배포, 로그인은 **범위 밖**이다.

### 데이터 흐름 5단계 (기획안 11.1)

```
① 사용자 → 브라우저    에디터에 글을 쓴다. 30초마다(또는 버튼) 스냅샷
② JS → Flask          fetch() POST — {세션, 시각, 내용, 이벤트 카운트}
③ Flask 내부          내용 해시 → 이전 해시와 연결해 hᵢ 계산
④ Flask → JSON 파일    data/chain.json 에 저장
⑤ Flask → JS → 화면    jsonify() → 타임라인·편집 곡선 렌더 → 검증 버튼
```

### 발표(데스크 크리틱)의 결정적 장면

1. F12 Network 탭을 열어둔 채 글을 쓰고 저장 → `snapshot` 요청이 흐르는 걸 보여준다
2. 화면에 초록 **"이 기록은 변조되지 않았습니다"**
3. `data/chain.json` 을 텍스트 편집기로 열어 `content_hash` 한 글자를 고친다
4. **"다시 검증"** 클릭 → 빨강 **"기록이 사후에 수정되었습니다"** + 몇 번째에서 깨졌는지

"데이터 흐름"과 "사후 조작 불가"를 한 장면에 담는다.

### API

| 엔드포인트 | 메서드 | 하는 일 |
|---|---|---|
| `/` | GET | `index.html` 서빙 (Jinja2 `render_template`) |
| `/api/snapshot` | POST | 스냅샷 1건을 체인에 추가. 작품·파일이 없으면 만든다. 빈 입력은 400 |
| `/api/exclude` | POST | 파일을 작품에서 뺀다. 이름은 지우고 "뺐다"는 사실만 남긴다 |
| `/api/verify` | GET | 체인 전체 반환 + 무결성 재계산 + 작품 루트 해시 + 지표 계산 |

### 해시 체인 (app.py의 심장)

```python
material = f"{prev_hash}|{time_str}|{content_hash}|{events_str}"
sha256(material)
```

`/api/verify` 는 저장된 재료로 해시를 **다시 계산해서** 파일에 적힌 값과 비교한다.

⚠️ 기획안 4.2는 "중간 하나만 고쳐도 이후가 전부 어긋난다"고 쓰여 있지만,
현재 구현은 **고친 그 한 줄만** 깨진다. 이유와 선택지는 [CHANGES.md](CHANGES.md) 9절 참고.

### 작품 루트 해시

```python
work_root = sha256("세션1 마지막 해시|세션2 마지막 해시|…")
```

세션마다 체인이 따로 돌기 때문에, 작품 전체를 대표하는 값이 따로 필요하다.
**증명서에 찍히고 외부 앵커에 고정되는 값이 이것이다.**

### chain.json 구조 — 작품 > 파일 > 세션 > 스냅샷

```json
{
  "works": [
    {
      "work_id": "w2",
      "title": "재이 커미션",
      "created_at": "2026-09-13T11:20:00",
      "files": [
        { "name": "러프.procreate", "first_seen": "2026-09-13T11:20:00" }
      ],
      "excluded": [ { "at": "2026-09-14T18:32:00" } ],
      "sessions": [
        {
          "session_id": "w2-s1",
          "file_name": "러프.procreate",
          "label": "러프",
          "started_at": "2026-09-13T11:20:00",
          "excluded": false,
          "snapshots": [
            {
              "seq": 0,
              "time": "2026-09-13T11:20:00",
              "chars": 0,
              "content_hash": "…",
              "events": { "typed": 0, "deleted": 0, "pasted": 0, "undo": 0 },
              "hash": "…"
            }
          ]
        }
      ]
    }
  ]
}
```

`excluded` 에는 **뺀 시각만** 들어간다. 파일 이름은 적지 않는다.
스냅샷 안쪽은 예전과 똑같다. 예전 구조(`sessions` 가 최상위)도 그대로 열린다.

`/api/verify` 는 여기에 세션별 `valid`·`broken_at`·`summary`, 작품별 `valid`·`root_hash`·`summary`·`files_summary`,
그리고 전체 `overall` 을 덧붙여 돌려준다.

### 화면 구조 (읽는 순서 = 구조)

```
① 판정      "이 기록은 변조되지 않았습니다"        ← 결론 먼저
② 한 줄 요약  기간·작품·파일·작업시간·붙여넣기·공백
③ 작품 카드  파일별 띠 → 뺀 파일 안내 → 작품 루트 해시 → 세션별 편집 곡선
④ 근거      스냅샷 체인 테이블 (접기)
⑤ 작성 영역  작품 이름 · 파일 이름 · 에디터 (접혀 있음 — 작가만 씀)
```

파일 띠의 **길이는 그 파일에 쓴 시간**이다. 밖에서 들어온 게 있으면 막대를 물들이지 않고
이름 앞에 주황 점을 찍는다 (막대를 칠하면 "이 파일이 통째로 외부"로 읽힌다).

### 지표 6개 (기획안 6.1) — 전부 서버가 계산

총 작업 시간 · 세션 수·간격 · 편집 곡선 · 붙여넣기 비율 · 되돌리기 횟수 · 공백 구간

`app.py` 의 `summarize()` 가 계산한다. **프런트는 그리기만 한다.**
유휴 판정 기준은 `IDLE_THRESHOLD = 180` (3분).

## 4. 실행 방법 (macOS)

```bash
conda activate cp

```

브라우저에서 `127.0.0.1:5001`

### 왜 5001 번인가

**5000 번은 맥의 AirPlay 수신기(ControlCenter)가 잡고 있다.**
IPv4 와 IPv6 양쪽을 다 잡기 때문에 `localhost:5000` 이나 `[::1]:5000` 으로 들어가면
우리 앱이 아니라 AirPlay 가 응답해서 **403** 이 뜬다.
`127.0.0.1:5000` 은 우리 앱으로 가지만, 한 번 403 을 받은 브라우저가 그걸 캐시해
계속 403 을 보여주는 일이 있었다.

시스템 설정을 건드리지 않아도 되게 **5001 번으로 옮겼다** (`app.py` 마지막 줄).
윈도우에는 이 문제가 없지만 팀원과 주소를 맞추기 위해 양쪽 다 5001 을 쓴다.

### 데모 데이터 만들기

```bash
python seed.py
```

데모 **작품 2개**를 기존 기록 뒤에 덧붙인다.

| 작품 | 내용 |
|---|---|
| 데모 1 — 처음부터 쓴 글 | 파일 1개 · 세션 3개 · 1시간 1분 · 붙여넣기 0% · 되돌리기 71 |
| 데모 2 — 붙여넣기가 많은 글 | 파일 1개 · 세션 1개 · 5분 · 붙여넣기 95% · 되돌리기 0 |
| 데모 3 — 파일 세 개짜리 그림 | 파일 3개 · 세션 3개 · 7시간 58분 · 뺀 파일 1개 |

**데모 1과 2는 같은 `에세이.docx` 인데 곡선이 정반대다.** 기획안 6.2 의 그림 두 개를
데이터로 만든 것이라, 발표에서 두 카드를 나란히 놓고 보여주면 된다.
제목에 "AI" 라는 말은 넣지 않았다 — 붙여넣기는 사실이고 AI 는 판정이다.

이미 `d1` 이 있으면 `d1-2` 처럼 번호를 붙여 겹치지 않게 한다.

⚠️ 데모 데이터를 손으로 고칠 때 **캡처 간격을 3분 넘기지 말 것.**
`IDLE_THRESHOLD = 180` 보다 간격이 길면 전부 "자리 비움"이 되어 작업 시간이 0이 된다.

세션끼리는 체인이 독립이다 — `/api/verify` 가 세션마다 GENESIS 부터 다시 계산한다.
그래서 뒤에 덧붙여도 기존 세션의 검증은 깨지지 않는다.

전부 지우고 데모 2개만 남기려면:

```bash
python seed.py --reset
```

`--reset` 은 현재 세션 목록을 보여주고 `yes` 를 정확히 입력해야만 진행한다.
지우기 직전에 `data/chain.backup.json` 으로 사본도 남긴다.

## 6. 회의에서 결정할 것

1. **스냅샷 간격 30초 / 60초** — `static/script.js` 첫 줄 `SNAPSHOT_INTERVAL` 상수
2. **외부 앵커(OpenTimestamps)를 이번 프로토타입에 넣을지** — 넣지 말 것을 권함.
   네트워크 변수 때문에 시연 중 깨질 위험. 로드맵에만 두고 화면엔 자리만 비워두기
3. **타임랩스 재생 — 기획안 내부 모순**
   6장은 화면 3에 "타임랩스 재생"을 넣었는데, 4.4·11.2는 "내용이 아닌 해시만 서버로"다.
   서버에 내용이 없으면 재생할 수 없다. 둘 중 하나를 고쳐야 한다.
   (원본을 로컬에 보관할지 / "타임랩스"를 "지표 재생"으로 바꿔 말할지)
4. **가격표 불일치** — 기획안 전문과 PPT가 다르다. 발표 전 통일할 것
