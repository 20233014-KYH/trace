## 1일 — 프로그램 · 서버 · 클라이언트

### 프로그램이란

**컴퓨터에게 시키는 일을 순서대로 적어 놓은 것.** 그게 전부입니다.

```
1. 지금 맨 앞에 뜬 창 이름을 알아낸다
2. 아까 것과 다르면 한 줄 적는다
3. 1초 쉰다
4. 1번으로 돌아간다
```

이게 우리 수집기입니다. **진짜로 이게 다입니다.**

### 서버란 — **24시간 켜져 있는 남의 컴퓨터**

식당으로 생각하면 쉽습니다.

```
    손님                     주방
  (클라이언트)              (서버)
     │                        │
     │   "김치찌개 하나"        │
     │ ──────────────────────▶ │
     │                        │
     │      김치찌개 나옴       │
     │ ◀────────────────────── │
```

| | 하는 일 | 우리 |
|---|---|---|
| **클라이언트** | 요청하는 쪽 | 수집기 · 화면 |
| **서버** | 받아서 처리하는 쪽 | `server/app.py` |

**손님은 주방에 안 들어갑니다.** 냄비가 어디 있는지 몰라도 "김치찌개요" 하면 나옵니다.

### 우리 서버는 지금 어디 있나

**내 맥북**입니다. `python server/app.py` 를 치면 내 컴퓨터가 잠깐 서버가 됩니다.

```
http://127.0.0.1:5000
     └─────┬────┘
      "이 컴퓨터" 라는 뜻
```

`127.0.0.1` 은 **"나 자신"** 을 가리키는 특별한 주소입니다. 그래서 **팀원 PC 에서는 안 닿습니다.**
10/7 관통 때 ngrok 이 필요한 이유가 이것입니다.

## 2일 — API · JSON

### API — **주문하는 창구**

어제 식당 이야기에서, 손님과 주방 사이의 **창구**가 API 입니다.

> **API** = Application Programming Interface
> 굳이 풀면 **"프로그램끼리 만나는 창구"**. 단어는 외울 필요 없습니다.

우리 창구는 이렇게 생겼습니다:

```
POST /api/sessions/{id}/events     ← 기록 보내기
GET  /api/sessions/{id}            ← 화면에 그릴 것 가져오기
POST /api/auth/login               ← 로그인
```

- **POST** = 뭔가 **보낸다**
- **GET** = 뭔가 **가져온다**

### JSON — **주고받는 글의 모양**

컴퓨터끼리 말할 때 쓰는 **약속된 글쓰기 방식**입니다.

```json
{
  "type": "copy",
  "len": 185,
  "hash": "a856267d723e…",
  "app": "Google Chrome"
}
```

읽는 법:

| 기호 | 뜻 |
|---|---|
| `{ }` | 한 덩어리 |
| `"type": "copy"` | **이름 : 값** |
| `,` | 다음 항목 |
| `"185"` 와 `185` | 따옴표 있으면 **글자**, 없으면 **숫자** |

**이게 우리 이벤트 한 줄입니다.** 수집기가 이런 걸 만들어서 서버로 보냅니다.

### 직접 보기 (5분)

```bash
cd ~/dev/trace/3-코드
head -2 data/events-*.jsonl
```

방금 배운 모양이 그대로 나옵니다.

### ✅ 오늘 끝나면

> "수집기가 **JSON** 한 줄씩 만들어서, **API** 로 서버에 보냅니다."

## 3일 — 데이터베이스 · 표

### DB 는 **엑셀 같은 것**입니다

칸이 있는 표에 줄 단위로 쌓입니다.

```
events 표
┌──────────────┬─────────────┬──────────┬─────┐
│ session_id   │ id          │ type     │ ts  │
├──────────────┼─────────────┼──────────┼─────┤
│ abc-123      │ evt_000001  │ window   │ …   │
│ abc-123      │ evt_000002  │ copy     │ …   │
└──────────────┴─────────────┴──────────┴─────┘
```

| 말 | 엑셀로 치면 |
|---|---|
| **표** (table) | 시트 한 장 |
| **행** (row) | 가로 한 줄 |
| **열** (column) | 세로 한 칸 |
| **기본키** (primary key) | **겹치면 안 되는 칸** |

### 기본키 — 우리가 실제로 겪은 문제

우리 이벤트 id 는 `evt_000001` 인데, **세션이 바뀌면 다시 1번부터** 시작합니다.

```
세션 A 의 evt_000001
세션 B 의 evt_000001     ← 같은 이름!
```

그래서 기본키를 **`(session_id, id)` 두 개 묶음**으로 잡았습니다. 이게
[`docs/api.md`](../docs/api.md) 의 "A 검토 수정 1곳" 입니다.

### 직접 보기 (10분)

```bash
sqlite3 3-코드/server/trace.db
```

```sql
.tables
SELECT type, count(*) FROM events GROUP BY type;
.quit
```

**영어지만 읽어 보세요.** `SELECT 무엇을 FROM 어디서` — 그냥 영어 문장입니다.

### ✅ 오늘 끝나면

> "SQLite 라는 **파일 하나**에 표로 저장됩니다. 배포할 때 주소만 바꿔서 Supabase 로 옮깁니다."

## 4일 — 프론트 · 백엔드 · 우리 구조

### 앞과 뒤

| | 뭐냐 | 우리 |
|---|---|---|
| **프론트엔드** | 사람이 **보는** 것 | `web/` (React) · `ui/viewer.html` |
| **백엔드** | 뒤에서 **처리**하는 것 | `server/app.py` + DB |

**"앞에서 보이는 것 / 뒤에서 도는 것"** 입니다.

### 우리 프로젝트 전체

```
[ 내 컴퓨터 ]
  수집기 (collector.py)  ← 창 · 복사 · 키 횟수를 본다
       │  events-날짜.jsonl 에 먼저 적고
       │
       ▼  5초마다 묶어서 보냄 (POST /events)
[ 서버 ]  app.py
       │  받은 걸로 해시를 다시 계산해 대조
       ▼
[ DB ]   trace.db
       │
       ▼  화면이 가져감 (GET /sessions/{id})
[ 화면 ]  React
```
