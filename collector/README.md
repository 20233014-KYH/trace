# Trace 수집기

컴퓨터를 켜두면 **뒤에서 조용히 돌면서, 어떤 프로그램을 보고 있었는지 적는** 프로그램입니다.

지금은 **3단계**입니다 — 화면에 찍고, **파일에도 남깁니다.**

찍고 남기는 것 두 가지:
- **[창]** 맨 앞에 뜬 프로그램이 바뀔 때
- **[복사]** 뭔가 복사할 때 — **내용은 안 보고 길이와 지문만**

---

## 파일이 뭐가 뭔지

| 파일 | 하는 일 | 누가 |
|---|---|---|
| `collector.py` | 1초마다 확인하고 바뀌면 한 줄 찍는다 | 같이 씀 |
| `platform_mac.py` | 맥에서 "지금 무슨 프로그램?"을 알아낸다 | A (맥) |
| `platform_win.py` | 윈도우에서 같은 일을 한다 | **다 만들어져 있음 (실행 확인만 필요)** |
| `storage.py` | 본 것을 파일에 남기고, 나중에 고쳐졌는지 검사한다 | 같이 씀 |

`collector.py` 는 지금이 맥인지 윈도우인지 보고 알아서 맞는 파일을 불러옵니다.
그래서 **두 사람이 각자 자기 것만 만들면 됩니다.**

## 기록은 어디에 남나

`trace/data/sessions/` 안에 **한 번 실행할 때마다 파일 하나**가 생깁니다.

```
data/sessions/2026-09-19_143002.jsonl
```

이 폴더는 **깃에 올라가지 않습니다.** 각자 자기 컴퓨터에만 있습니다.
기획안 4.3 "모든 기록은 학생 PC의 로컬 파일에 먼저 쓰이고,
공유는 세션 단위로 학생이 결정한다" 를 지키는 것입니다.

**`.jsonl` 이 뭔가** — 한 줄이 기록 하나입니다. 뒤에 붙이기만 합니다.

| | 저장할 때 | 도중에 컴퓨터가 꺼지면 |
|---|---|---|
| `.json` | 매번 **전체**를 다시 씀 | 파일 전체가 깨질 수 있음 |
| `.jsonl` | **한 줄만** 뒤에 붙임 | 앞부분은 멀쩡함 |

실제로 들어 있는 한 줄은 이렇게 생겼습니다.

```json
{"seq": 2, "time": "2026-09-19T15:21:34", "type": "app",
 "data": {"app": "Claude", "title": null},
 "prev": "2dbd4ce8...", "hash": "c6b66282..."}
```

**복사한 글의 원문은 어디에도 없습니다.** 길이와 지문만 있습니다.

---

## 왜 줄마다 지문이 붙나 (= 해시 체인)

기록이 그냥 텍스트 파일이면, **나중에 메모장으로 열어서 고치면 그만**입니다.
그러면 "과정을 기록했다"는 말이 아무 의미가 없습니다.

그래서 각 줄의 지문을 이렇게 만듭니다.

```
이번 줄 지문 = SHA256( 앞줄 지문 + 시각 + 종류 + 내용 )
                       ↑ 이게 핵심
```

**앞줄의 지문이 재료에 들어갑니다.** 그래서 3번째 줄을 몰래 고치면

- 3번의 지문이 달라지고
- 4번은 3번의 지문을 재료로 썼으므로 4번도 어긋나고
- 그 뒤가 **도미노처럼 전부 어긋납니다**

한 줄만 고치고 넘어가는 것이 불가능해집니다.
줄을 **지우거나 끼워넣는 것도** 연결이 끊어져서 바로 드러납니다.

### 직접 확인하는 법

```bash
python storage.py
```

이게 자가진단입니다. 멀쩡한 파일을 만들고, 일부러 고쳐 보고, 일부러 지워 보고,
**잡아내는지** 확인합니다. 실제 결과:

```
  ✅ 기록 만들기      2026-09-19_152110.jsonl
  ✅ 검사 (정상)      4줄 모두 정상
  ✅ 검사 (조작)      3번째 줄에서 잡아냄
                      이유: 줄의 내용이 고쳐졌습니다
  ✅ 검사 (삭제)      2번째 줄에서 잡아냄
                      이유: 앞줄과의 연결이 끊어졌습니다 (줄을 지웠거나 끼워넣었습니다)
```

내 기록 파일을 직접 검사하려면 뒤에 파일 이름을 붙입니다.

```bash
python storage.py ../data/sessions/2026-09-19_143002.jsonl
```

### 주의 — 지문이 보장하는 것과 못 하는 것

| | |
|---|---|
| ✅ 보장함 | 이 기록이 **만들어진 뒤에 고쳐지지 않았다** |
| ❌ 못 함 | 기록된 내용이 **사실이다** |
| ❌ 못 함 | 이 사람이 **직접 했다** |

수집기를 끄고 작업하면 아무것도 안 남습니다. 지문은 그것까지 막지 못합니다.
기획안의 Learn 모드(내 회고용)에는 사실 지문이 필요 없습니다.
**Proof 모드(남을 설득할 때)** 를 위해 지금부터 깔아 두는 것입니다.

## 맥은 창 제목이 안 나옵니다

프로그램 이름만 나오고 창 제목은 비어 있습니다.
맥은 다른 프로그램의 창 제목을 읽으려면 **시스템 설정 → 개인정보 보호 → 화면 기록** 권한이 필요하기 때문입니다.

윈도우는 권한 없이도 창 제목까지 나옵니다. 그래서 **윈도우 쪽 기록이 더 자세합니다.**

1단계에서는 프로그램 이름만으로 충분합니다.

---

## 붙여넣기는 왜 안 잡히나

**복사는 클립보드를 바꾸지만, 붙여넣기는 아무것도 바꾸지 않는다.**
그래서 지금 방식으로는 원리적으로 잡을 수 없다.

붙여넣기를 잡으려면 **키 입력(Ctrl+V / ⌘V)을 봐야** 한다.

| | 필요한 권한 |
|---|---|
| 윈도우 | 없음 |
| 맥 | 시스템 설정 → 개인정보 보호 → **손쉬운 사용** |

4단계(그리기) 다음에 붙인다.

## 다음에 붙일 것

| 단계 | 무엇을 | 상태 |
|---|---|---|
| 1 | 창이 바뀌면 화면에 찍기 | ✅ 완료 |
| 2 | 복사도 찍기 — **길이와 해시만, 내용은 안 봄** | ✅ 완료 |
| 3 | 파일에 저장 + 고쳐졌는지 검사 | ✅ 지금 여기 |
| 4 | 브라우저에 시간 막대로 그리기 | 다음 |
| 5 | "자료 → AI → 붙여넣기" 판별 | |

한 단계씩. **한꺼번에 만들지 않습니다.**

## 만들면서 겪은 문제 (설명할 수 있어야 하는 것)

**증상** — 창을 바꿔도 직전 프로그램 이름이 계속 찍혔다. 한 박자씩 늦었다.

**원인** — 맥은 "지금 어떤 프로그램이 활성이다" 같은 소식을 우리 프로그램의
**우편함**에 넣어 둔다. 우리가 우편함을 열어보지 않으면, 맥에게 물어봐도
예전에 받아둔 옛날 소식을 그대로 돌려준다.

**해결** — 읽기 직전에 우편함을 0.05초만 열었다 닫는다.
`platform_mac.py` 의 `NSRunLoop...` 한 줄이 그것이다.

| | 결과 |
|---|---|
| 그냥 읽기 | Finder, Finder, Claude, Finder — 계속 한 박자 늦음 |
| 우편함 열고 읽기 | Finder, Claude, Finder, Claude — 정확 |

윈도우에는 이 문제가 없다. `GetForegroundWindow()` 는 물어보면 바로 지금 값을 준다.

## 왜 클립보드를 '번호'와 '지문'으로 나눠 보나

`platform_mac.py` 에 복사 관련 함수가 **두 개** 있다.

| 함수 | 하는 일 | 내용을 읽나 |
|---|---|---|
| `clipboard_serial()` | 바뀔 때마다 1씩 오르는 번호만 확인 | ❌ 안 읽음 |
| `clipboard_digest()` | 길이와 지문을 잼 | 읽지만 **바로 버림** |

평소에는 번호만 본다. **번호가 바뀌었을 때만** 길이를 잰다.
1초마다 남의 클립보드 내용을 들여다보지 않기 위해서다.

기획안 4.3 "클립보드는 길이와 SHA256만" 을 코드로 지키는 방법이다.

**지문(해시)이란** — 아무리 긴 글도 넣으면 64자리 값이 나온다.
같은 글은 늘 같은 값, 한 글자만 달라도 완전히 다른 값이 나온다.
그래서 "AI 탭에서 복사한 것"과 "워드에 붙여넣은 것"이 같은지를
**내용을 보지 않고** 비교할 수 있다.

글자가 아닌 것(사진·파일)을 복사하면 `글자가 아닌 것` 으로만 남는다.
