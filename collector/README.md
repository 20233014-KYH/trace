# Trace 수집기

컴퓨터를 켜두면 **뒤에서 조용히 돌면서, 어떤 프로그램을 보고 있었는지 적는** 프로그램입니다.

지금은 **3단계**입니다 — 화면에 찍고, **파일에도 남깁니다.**

찍고 남기는 것 세 가지:
- **[창]** 맨 앞에 뜬 프로그램이 바뀔 때
- **[복사]** 뭔가 복사할 때 — **내용은 안 보고 길이와 지문만**
- **[붙임]** 뭔가 붙여넣을 때 — **어디에 붙였는지까지**

---

## 파일이 뭐가 뭔지

| 파일 | 하는 일 | 누가 |
|---|---|---|
| `collector.py` | 1초마다 확인하고 바뀌면 한 줄 찍는다 | 같이 씀 |
| `platform_mac.py` | 맥에서 "지금 무슨 프로그램?"을 알아낸다 | A (맥) |
| `platform_win.py` | 윈도우에서 같은 일을 한다 | **다 만들어져 있음 (실행 확인만 필요)** |
| `storage.py` | 본 것을 파일에 남기고, 나중에 고쳐졌는지 검사한다 | 같이 씀 |
| `test_paste.py` | 붙여넣기 판별이 맞는지 가짜 키 입력으로 시험한다 | 같이 씀 |
| `check_permission.py` | 맥에서 붙여넣기가 왜 안 잡히는지 짚어준다 | A (맥) |

`collector.py` 는 지금이 맥인지 윈도우인지 보고 알아서 맞는 파일을 불러옵니다.
그래서 **두 사람이 각자 자기 것만 만들면 됩니다.**

## 기록은 어디에 남나

`trace/data/sessions/` 안에 **한 번 실행할 때마다 파일 하나**가 생깁니다.

```
data/sessions/2026-09-19_143002.jsonl
```

이 폴더는 **깃에 올라가지 않습니다.** 각자 자기 컴퓨터에만 있습니다.
기획안 4.3 "모든 기록은 학생 PC의 로컬 파일에 먼저 쓰이고,
공유는 세션 단위로 학생이 결정한다" 를 지키는 것입니다.

**`.jsonl` 이 뭔가** — 한 줄이 기록 하나입니다. 뒤에 붙이기만 합니다.

| | 저장할 때 | 도중에 컴퓨터가 꺼지면 |
|---|---|---|
| `.json` | 매번 **전체**를 다시 씀 | 파일 전체가 깨질 수 있음 |
| `.jsonl` | **한 줄만** 뒤에 붙임 | 앞부분은 멀쩡함 |

실제로 들어 있는 한 줄은 이렇게 생겼습니다.

```json
{"seq": 2, "time": "2026-09-19T15:21:34", "type": "app",
 "data": {"app": "Claude", "title": null},
 "prev": "2dbd4ce8...", "hash": "c6b66282..."}
```

**복사한 글의 원문은 어디에도 없습니다.** 길이와 지문만 있습니다.

---

## 왜 줄마다 지문이 붙나 (= 해시 체인)

기록이 그냥 텍스트 파일이면, **나중에 메모장으로 열어서 고치면 그만**입니다.
그러면 "과정을 기록했다"는 말이 아무 의미가 없습니다.

그래서 각 줄의 지문을 이렇게 만듭니다.

```
이번 줄 지문 = SHA256( 앞줄 지문 + 시각 + 종류 + 내용 )
                       ↑ 이게 핵심
```

**앞줄의 지문이 재료에 들어갑니다.** 그래서 3번째 줄을 몰래 고치면

- 3번의 지문이 달라지고
- 4번은 3번의 지문을 재료로 썼으므로 4번도 어긋나고
- 그 뒤가 **도미노처럼 전부 어긋납니다**

한 줄만 고치고 넘어가는 것이 불가능해집니다.
줄을 **지우거나 끼워넣는 것도** 연결이 끊어져서 바로 드러납니다.

### 직접 확인하는 법

```bash
python storage.py
```

이게 자가진단입니다. 멀쩡한 파일을 만들고, 일부러 고쳐 보고, 일부러 지워 보고,
**잡아내는지** 확인합니다. 실제 결과:

```
  ✅ 기록 만들기      2026-09-19_152110.jsonl
  ✅ 검사 (정상)      4줄 모두 정상
  ✅ 검사 (조작)      3번째 줄에서 잡아냄
                      이유: 줄의 내용이 고쳐졌습니다
  ✅ 검사 (삭제)      2번째 줄에서 잡아냄
                      이유: 앞줄과의 연결이 끊어졌습니다 (줄을 지웠거나 끼워넣었습니다)
```

내 기록 파일을 직접 검사하려면 뒤에 파일 이름을 붙입니다.

```bash
python storage.py ../data/sessions/2026-09-19_143002.jsonl
```

### 주의 — 지문이 보장하는 것과 못 하는 것

| | |
|---|---|
| ✅ 보장함 | 이 기록이 **만들어진 뒤에 고쳐지지 않았다** |
| ❌ 못 함 | 기록된 내용이 **사실이다** |
| ❌ 못 함 | 이 사람이 **직접 했다** |

수집기를 끄고 작업하면 아무것도 안 남습니다. 지문은 그것까지 막지 못합니다.
기획안의 Learn 모드(내 회고용)에는 사실 지문이 필요 없습니다.
**Proof 모드(남을 설득할 때)** 를 위해 지금부터 깔아 두는 것입니다.

## 붙여넣기

복사와 붙여넣기는 **잡는 방법이 완전히 다릅니다.**

| | 클립보드를 바꾸나 | 어떻게 잡나 |
|---|---|---|
| **복사** | ✅ 바꿈 | 클립보드 번호가 오르는 걸 본다 |
| **붙여넣기** | ❌ 안 바꿈 | **키(⌘V / Ctrl+V)를 직접 봐야 한다** |

그래서 붙여넣기만 따로 만들었습니다. 이렇게 찍힙니다.

```
  15:23:29  [복사]  185글자   지문 1416111db656…             ·880ac77c
  15:24:21  [창]   Microsoft PowerPoint                     ·7041ab22
  15:24:25  [붙임]  185글자   지문 1416111db656… → Microsoft PowerPoint  ·5d627ff9
```

**지문이 같습니다.** 크롬에서 복사한 것을 PowerPoint 에 그대로 붙였다는 뜻입니다 —
**내용을 하나도 보지 않고** 알아낸 것입니다. 이게 5단계
"자료 → AI → 붙여넣기" 판별의 재료가 됩니다.

### 맥은 권한이 **두 개**입니다 (여기서 한참 헤맸습니다)

| 권한 | 뜻 | 붙여넣기에 필요한가 |
|---|---|---|
| **손쉬운 사용** | 컴퓨터를 **조작**해도 된다 (마우스를 움직이고 클릭하고) | ❌ |
| **입력 모니터링** | 키 입력을 **들어도** 된다 | ✅ **이것** |

**완전히 다른 목록입니다.** 손쉬운 사용만 켜면 붙여넣기는 안 잡힙니다.
이름이 비슷해서 손쉬운 사용만 켜고 "왜 안 되지" 하기 딱 좋습니다.

**시스템 설정 → 개인정보 보호 및 보안 → 입력 모니터링** 에서
**터미널**을 켜고, **터미널을 ⌘Q 로 완전히 껐다 켜세요.**
(맥은 껐다 켜야 권한이 반영됩니다. 창만 닫는 건 안 됩니다)

안 되면 진단 파일을 돌려보세요. 어디가 막혔는지 짚어줍니다.

```bash
python check_permission.py
```

```
  손쉬운 사용    ✅ 켜짐
  입력 모니터링  ❌ 거부됨/꺼짐     ★ 붙여넣기는 이게 있어야 합니다
```

권한이 다 있으면 실제로 ⌘V 를 눌러보게 하고 **정말 소식이 오는지**까지 확인합니다.

안 켜도 창·복사 기록은 정상으로 남습니다. 붙여넣기만 안 보입니다.

**윈도우는 권한이 하나도 필요 없습니다.** 바로 됩니다.

### 키를 훔쳐보는 것 아닌가 (솔직한 답)

**맥은 어떤 키를 누르든 소식이 옵니다.** "V 키만 알려줘" 같은 주문을 맥이 받아주지 않기 때문입니다.
`platform_mac.py` 의 `_키를_눌렀을때()` 가 하는 일은 딱 이것뿐입니다.

```python
커맨드를_같이_눌렀나 = bool(이벤트.modifierFlags() & NSEventModifierFlagCommand)
if 커맨드를_같이_눌렀나 and 이벤트.keyCode() == V_키:
    _붙여넣기_횟수 += 1
# ← 함수가 여기서 끝난다. 다른 키는 쳐다보지도 않고 버려진다.
```

**무슨 글자를 쳤는지는 세지도, 적지도, 저장하지도 않습니다.** 기록에 남는 것은
"몇 시 몇 분에 붙여넣었다 / 몇 글자였다 / 어디에 붙였다" 뿐입니다.

**윈도우는 이보다도 덜 봅니다.** `GetAsyncKeyState` 로
**Ctrl, Shift, V, Insert 네 개만** "지금 눌려 있나?" 하고 물어봅니다.
다른 키는 물어보지도 않습니다.

윈도우에서 흔히 쓰는 **키 후킹은 일부러 안 썼습니다.** 모든 키 입력이 우리 프로그램을
거쳐 가게 만드는 방식이라, 우리 쪽이 잠깐만 버벅여도 **컴퓨터 전체의 키 입력이 같이 느려집니다.**

### 맞는지 어떻게 확인했나

```bash
python test_paste.py
```

진짜 키보드를 치지 않고 **가짜 키 입력**을 넣어서, ⌘V / Ctrl+V 만 골라내는지 봅니다.
**맥에서 윈도우 코드까지 같이 시험합니다** (팀원 컴을 빌리지 않아도 됩니다).

```
  맥 — ⌘V 만 골라내나
  ✅  ⌘V  (붙여넣기)           셈 1  (기대 1)
  ✅  ⌘⇧V (서식없이 붙여넣기)   셈 1  (기대 1)
  ✅  ⌘C  (복사)               셈 0  (기대 0)
  ✅  그냥 V 타이핑            셈 0  (기대 0)

  윈도우 — Ctrl+V 만 골라내나
  ✅  Ctrl+V  (붙여넣기)       셈 1  (기대 1)
  ✅  Shift+Insert (옛날 방식) 셈 1  (기대 1)
  ✅  Ctrl+C  (복사)           셈 0  (기대 0)
  ✅  Ctrl+V 를 2초간 꾹       셈 1  (기대 1)
  ✅  Ctrl+V 두 번             셈 2  (기대 2)
```

이 시험이 통과해도 **"진짜 키보드에서 잘 잡힌다"는 보장은 아닙니다.**
그건 실제로 수집기를 켜고 붙여넣어 봐야 압니다.

## 만들면서 겪은 문제 (설명할 수 있어야 하는 것)

**증상** — 창을 바꿔도 직전 프로그램 이름이 계속 찍혔다. 한 박자씩 늦었다.

**원인** — 맥은 "지금 어떤 프로그램이 활성이다" 같은 소식을 우리 프로그램의
**우편함**에 넣어 둔다. 우리가 우편함을 열어보지 않으면, 맥에게 물어봐도
예전에 받아둔 옛날 소식을 그대로 돌려준다.

**해결** — 읽기 직전에 우편함을 0.05초만 열었다 닫는다.
`platform_mac.py` 의 `NSRunLoop...` 한 줄이 그것이다.

| | 결과 |
|---|---|
| 그냥 읽기 | Finder, Finder, Claude, Finder — 계속 한 박자 늦음 |
| 우편함 열고 읽기 | Finder, Claude, Finder, Claude — 정확 |

윈도우에는 이 문제가 없다. `GetForegroundWindow()` 는 물어보면 바로 지금 값을 준다.

## 왜 클립보드를 '번호'와 '지문'으로 나눠 보나

`platform_mac.py` 에 복사 관련 함수가 **두 개** 있다.

| 함수 | 하는 일 | 내용을 읽나 |
|---|---|---|
| `clipboard_serial()` | 바뀔 때마다 1씩 오르는 번호만 확인 | ❌ 안 읽음 |
| `clipboard_digest()` | 길이와 지문을 잼 | 읽지만 **바로 버림** |

평소에는 번호만 본다. **번호가 바뀌었을 때만** 길이를 잰다.
1초마다 남의 클립보드 내용을 들여다보지 않기 위해서다.

기획안 4.3 "클립보드는 길이와 SHA256만" 을 코드로 지키는 방법이다.

**지문(해시)이란** — 아무리 긴 글도 넣으면 64자리 값이 나온다.
같은 글은 늘 같은 값, 한 글자만 달라도 완전히 다른 값이 나온다.
그래서 "AI 탭에서 복사한 것"과 "워드에 붙여넣은 것"이 같은지를
**내용을 보지 않고** 비교할 수 있다.

글자가 아닌 것(사진·파일)을 복사하면 `글자가 아닌 것` 으로만 남는다.
